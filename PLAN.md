# PLAN — ai-report-generator

Engineering plan behind the project: what is being built, in which order, and how each
part is verified.

## 1. Goals
- A browser app that turns **free-form notes into a polished .pptx deck** through an LLM:
  paste raw material, pick an analysis mode, download a branded slide deck.
- The LLM layer is a **small interface with a deterministic mock** — the whole app is
  testable and demonstrable without an API key or network.
- Production hygiene from day one: **login gate**, **usage logging** of every generation
  (CSV-exportable), env-driven configuration, one-command deploy.

## 2. Scope
| Layer | Module | What ships |
|---|---|---|
| LLM | `core/llm.py` | `LLM` interface; `AnthropicLLM` (Claude Messages API) and `MockLLM` (deterministic, offline); provider selected by env. |
| Analysis | `core/modes.py` | Three research modes over the same input, one strict JSON contract: `weekly summary`, `risk flags`, `next week`. Prompt builders + a validating parser (markdown fences tolerated, malformed JSON rejected). |
| Deck | `core/deck.py` | python-pptx builder on a branded template (16:9): title slide + one section slide per block. Template generated by `make_template.py`, swappable per client. |
| Auth | `core/auth.py` | scrypt password hashing, user table, first-run default admin. |
| Usage | `core/usage.py` | every generation logged (user, mode, size, duration) → CSV export. |
| UI | `app.py` | Streamlit: login, notes, mode, generate, preview, .pptx download, usage sidebar. |

The demo domain is an **Engineering Weekly Digest**: teams paste standup/incident/release
notes and get a slide-ready digest — the layering (LLM → structured JSON → deck) is
domain-free and the template + prompts are what a client would swap.

## 3. Milestones
- **M1 — LLM + modes**: interface, mock provider, 3 mode prompts, validating parser.
  *Done when:* unit tests generate + parse digests offline.
- **M2 — deck builder**: template generation + digest → .pptx.
  *Done when:* tests assert slide count and round-trip the file through python-pptx.
- **M3 — auth + usage**: scrypt users, default admin, generation log + CSV.
  *Done when:* tests cover login success/failure and CSV columns.
- **M4 — Streamlit UI**: login gate, generation flow, download, usage sidebar.
  *Done when:* app boots with `streamlit run app.py` and completes a mock generation.
- **M5 — docs + demo assets**: README with screenshots, deploy config.

## 4. Test strategy (pytest)
- `MockLLM` everywhere — no API key, no network, deterministic content.
- Modes: fenced-JSON parsing, schema validation, malformed output rejected.
- Deck: slide counts from a known digest; generated template opens in python-pptx.
- Auth: salted hashes differ per user; wrong password rejected.
- Usage: rows written per generation, CSV parses back with expected columns.
- The Streamlit layer is kept intentionally thin (forms + calls), so logic tests live in
  `core/`; a manual mock-mode walkthrough covers the UI.

## 5. Demo & docs
- README screenshots: login, generation form, produced deck metadata (mock mode).
- `python make_template.py` regenerates the branded template; point `PPTX_TEMPLATE`
  at a client's .pptx to rebrand.

## 6. Roadmap (client-specific work, intentionally not bundled)
- Real template ingestion from arbitrary client decks (placeholder-name mapping).
- Longer inputs: chunking + map-reduce summarisation; token/cost budgeting.
- Scheduled e-mail delivery of the digest; multi-tenant workspaces.

## 7. Definition of Done
`pytest` green; `streamlit run app.py` completes a full mock generation to .pptx;
usage CSV downloadable; clean commit history.
